# 人工验收清单

这份清单用于补齐自动化测试无法证明的真实客户端行为。每一项记录“通过／失败／未测试”和实际截图或文字结果。不要把“未测试”填写为“通过”。

## 前置条件

- Windows 上已安装并能正常打开 Codex 桌面客户端。
- 已按客户端提供的本地插件流程加载 `context-prompt-assistant`。
- 使用新对话测试，避免旧对话缓存 Skill 或工具定义。
- 准备一个可分享的 Codex 任务链接；不要在链接中包含 token、密码或其他凭据。
- 若测试真实线程读取，确认当前 Codex App Server 正在运行；不能运行时记录为“降级路径测试”。

## A. 当前对话模式（Codex）

操作：调用 `context-prompt-assistant`，输入“优化下一条指令，只输出提示词，暂不执行：把刚才那个页面改紧凑点，之前说的功能别删”。

预期：

- 输出“优化后的提示词”“待确认／可选建议”“上下文状态”三部分。
- 保留“改紧凑”和“之前的功能不能删除”。
- 不修改文件、不运行命令、不发送下一条任务。
- 找不到“刚才那个页面”时提出待确认问题，不虚构页面名称。

通过标准：连续测试 3 次，结构和边界均符合预期。

## B. Codex 链接模式

操作：在专用优化对话粘贴真实 Codex 链接，输入“结合这个任务的最新上下文，优化：继续完成刚才的修复，并补上测试”。

预期：

- 正确识别提供方、目标类型和目标 ID。
- App Server 可用时，显示实际读取范围和检查时间。
- App Server 不可用时，显示不可访问原因和回到原对话的短指令。
- 不把“链接解析成功”描述为“历史已完整读取”。

通过标准：成功读取与不可读取两条路径都各测试一次，并保存结果。

## C. ChatGPT 当前对话与链接

操作：在 ChatGPT 桌面端分别测试当前对话调用 Skill，以及粘贴 `chatgpt.com/c/...` 私有链接。

预期：

- 当前对话模式能按 Skill 输出三部分。
- 私有链接只报告解析／访问状态；不可读时给出原对话降级指令。
- 不使用 Cookie、网页抓取或外接 API。

通过标准：结果与 Codex 模式边界一致，且没有声称读取了未提供的历史。

## D. 回归与安全

- 原始指令中的数字、路径、否定条件和“暂不执行”均保留。
- 切换另一个目标后，不出现上一个目标的内容。
- 超长内容显示截断标记。
- 包含敏感 query 参数的测试链接不会在结果中回显。
- 断开 App Server 后，工具仍能正常返回结构化降级状态。

## E. Windows 伴随窗口

前置：执行 `npm ci` 后运行 `npm run dev`，确认本机 Codex CLI 已登录。若未安装 Electron 二进制，记录为“环境阻塞”，不能填写“通过”。

操作：

1. 打开窗口，将一个 Codex 任务链接粘贴到目标输入框，点击“绑定”。
2. 检查目标 ID、访问状态和读取范围；再输入“继续完成刚才的修复，并补上测试”，按 Ctrl+Enter。
3. 点击“复制”，粘贴到纯文本编辑器核对结果；切换置顶并重启应用。
4. 绑定第二个目标，再次优化，确认前一个目标的正文没有混入。

预期：

- 窗口可在 Codex 旁边使用，输入和结果区域不会访问 Node API。
- 每次生成前刷新；不可读或刷新失败时显示相应状态，不伪称参考了最新历史。
- 优化会话使用只读沙箱，源项目没有文件变更、任务续跑或自动发送。
- 复制内容与结果显示一致；置顶状态实际影响窗口；切换目标后内容隔离。

通过标准：以上步骤在干净安装环境完成一次，成功和不可读路径各记录一次；任一安全边界失败则整项失败。

## F. 发布材料

- `npm ci`、`npm run check`、`npm test`、`npm run validate` 全部成功。
- `npm run package:win` 生成 NSIS 和 portable 两种包，安装路径包含空格和中文时仍可启动。
- GitHub 仓库不包含会话历史、令牌、缓存或本地配置；README 明确第三方性质与已知限制。

## G. 真实 Codex App Server 历史读取

官方 App Server 的 `thread/read` 是只读读取已存线程；设置 `includeTurns: true` 才会返回轮次内容。它不会恢复线程、订阅事件或继续执行任务。[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)

### 用户测试步骤

1. 在与 Codex 相同的 Windows 用户环境打开 PowerShell，运行 `codex login status`。应显示当前登录方式和账号状态；不要把任何 token 或 `auth.json` 内容发出来。
2. 进入项目目录并列出最近任务：

   ```powershell
   cd D:\CodexProjects\context-prompt-assistant
   node scripts/app-server-diagnostics.mjs
   ```

   记录一个你愿意用于测试的 `id`、任务名称和 `count`。该命令只请求 `thread/list`，不会运行任务。
3. 用上一步的 ID 读取历史：

   ```powershell
   node scripts/app-server-diagnostics.mjs --read <thread-id>
   ```

   预期得到 `ok: true`、线程名称、轮次数量和末尾样本。只把 `ok`、`id`、`name`、`turns`、`characters` 和错误原因反馈给开发者；样本可能包含私密对话，不要直接粘贴。
4. 在伴随应用中绑定对应的 Codex 链接。若客户端链接无法解析，可以在确认 ID 后使用 `codex://thread/<thread-id>` 做本地测试输入；这只是在本地适配器中指向同一线程，不是公开分享链接。
5. 绑定后输入一条不会修改代码的测试原话，例如“只根据刚才的上下文列出当前未解决问题，不要执行任何操作”，点击优化。确认窗口显示读取轮次和检查时间，结果包含上下文状态，源任务没有新增轮次或文件变更。
6. 在原 Codex 任务中追加一条无敏感信息的明确修正，再次点击优化。确认第二次结果反映修正；如果读取失败，界面必须显示不可访问或缓存过期，不能声称已读取最新历史。

### 反馈格式

```text
Codex 版本：
codex login status：成功／失败（不要填写 token）
thread/list：成功／失败，count：
thread/read：成功／失败，turns：，characters：
伴随窗口绑定：成功／失败
刷新后是否反映修正：是／否／未测试
是否修改源项目或续跑任务：是／否
错误信息（去掉路径中的敏感信息）：
```

当前开发环境已用同一诊断脚本实测：`thread/list` 返回 7 个线程，`thread/read` 成功读取一个 10 轮次线程。第一次无提升权限运行时因 `D:\CodexHome` 的 sqlite 状态目录权限失败；提升权限后通过。这证明适配器协议路径可用，但不能替代你在 Codex 桌面客户端中的人工验收。
